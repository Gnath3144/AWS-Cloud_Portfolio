DOMAIN 01 • Gnath3144/AKEF

Deterministic Knowledge Compilers (AST → Knowledge IR → Scene IR)

Multi-Pass Compiler

1. The Engineering Problem

LLM-generated educational content and technical presentations suffer from structural drift, hallucinated grammar, and poor alignment with strict enterprise learning objectives. Standard prompting lacks deterministic compilation guarantees.

2. Architectural Decision

Adopted a traditional four-pass compiler pipeline: Raw Markdown input is lexed into a structured AST, enriched through a Knowledge Reasoning Graph (Knowledge IR), formatted into layout-agnostic Scene IR, and rendered into verified PowerPoint (.pptx) and PDF artifacts.

Key Challenge & Solution: Rendering high-density vector diagrams without external rendering engine crashes. Resolved by emitting self-contained XML/Scene IR with mathematical bounding constraints.

DOMAIN 02 • Gnath3144/langgraph-financial-ai-agent

Stateful Agentic Graphs & Quantitative Market Intelligence

LangGraph State Machine

1. The Engineering Problem

Single-turn LLM financial analyzers fail when handling multi-step research requiring real-time market data retrieval, SEC 10-K parsing, balance sheet ratio computation, and risk reconciliation in parallel. Prompt-only chains lack memory checkpoints and fail non-deterministically.

2. Architectural Decision

Implemented a cyclic LangGraph state machine: A Supervisor Router orchestrates parallel worker nodes (SEC 10-K Scraper, Quantitative Valuation Engine, and Risk & Compliance Auditor). State dictionaries pass across edges with SQLite checkpointer persistence and human-in-the-loop audit gates.

Key Challenge & Solution: Handling rate limits and schema inconsistencies across financial APIs. Built asynchronous retry backoffs with Pydantic contract validation, reducing LLM token overhead by 48%.
LangGraph Multi-Agent State Machine

DOMAIN 03 • Gnath3144/data-engineering

Enterprise AWS & Databricks Medallion Streaming Lakehouse

PySpark & Delta Lake

1. The Engineering Problem

High-throughput IoT & financial telemetry ingestion creates severe small-file bottlenecks, schema drift, and unmanageable query latency across downstream BI and analytical workloads.

2. Architectural Decision

Architected a Medallion Lakehouse on AWS S3 & Databricks Delta Lake: Kafka streams land in Bronze S3 tables, cleansed and deduplicated via PySpark Structured Streaming into Silver tables, and aggregated into Z-Ordered Gold marts for sub-second analytical queries.

Key Challenge & Solution: Eliminating ACID write conflicts across concurrent micro-batches. Resolved by implementing Delta Lake Serializable Isolation and automated OPTIMIZE compaction jobs.

DOMAIN 04 • Gnath3144/retail-sales-warehouse-snowflake

Snowflake Retail Cloud Data Warehouse & Auto-Ingest

Snowflake & Snowpipe

1. The Engineering Problem

Traditional on-premise relational databases suffer from compute and storage contention during peak retail sales reporting, resulting in degraded dashboard rendering and slow ETL locks.

2. Architectural Decision

Engineered an isolated multi-cluster virtual warehouse on Snowflake with dimensional Star Schema modeling (`FACT_DAILY_SALES`, `DIM_CUSTOMER`, `DIM_PRODUCT`, `DIM_STORE`). Automated Continuous Ingestion via Snowpipe with SQS notification triggers.

Key Challenge & Solution: Zero cluster contention for executive dashboards. Used separate virtual warehouses for Ingestion (X-Small) and BI DirectQuery (Medium) with auto-suspend policies.
